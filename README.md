# Агент для вопросов о свежих событиях

Любая языковая модель, даже самая сильная, знает мир только до даты среза своих знаний. Спросите её, сколько людей погибло в аварии в апреле 2026 года, и она либо ответит «не знаю», либо уверенно назовёт неверное число. Размер модели здесь не помогает: нужного факта нет в её весах, его приходится приносить извне - поиском, базой знаний, памятью. Поэтому модели дают инструменты.

Но если факты приносят инструменты, дорогая модель может оказаться лишней. Тезис проекта: **дешёвая модель с хорошими инструментами отвечает на свежие вопросы не хуже сильной, а верный ответ у неё стоит в разы меньше.**

Тезис проверяется на 155 вопросах о событиях 2025-2026 годов, на которые сильная модель без инструментов не отвечает. Главная метрика - цена одного верного ответа: все траты варианта делятся на число его верных ответов.

Агент написан на чистом Python без фреймворков, модели вызываются через [OpenRouter](https://openrouter.ai).

## Этапы

Проект развивается этапами. Каждый этап проверяет новую идею на тех же вопросах и добавляет свои строки в общую таблицу результатов.

| Этап | Идея | Подробности |
|---|---|---|
| 1. ReAct-агент с живым поиском | Дешёвая модель сама ходит в Википедию и на новостные сайты и дочитывает найденную страницу | [docs/01-react-agent.md](docs/01-react-agent.md) |
| 2. RAG и память | Нужные тексты заранее лежат в векторной базе, модель получает пять нужных строк вместо всей страницы. Агент запоминает факты о пользователе, а не носит с собой всю историю диалога | [docs/02-rag-memory.md](docs/02-rag-memory.md) |

## Выводы

### Этап 1. ReAct-агент с живым поиском

1. **Сильная модель без инструментов на свежих вопросах не справляется:** 4 % верных ответов, $0.057 за верный ответ.
2. **Тезис подтверждается.** Дешёвая модель со всеми источниками точнее сильной в 11 раз (45 % против 4 %), а верный ответ у неё дешевле в 29 раз ($0.002 против $0.057).
3. **Средняя модель с теми же инструментами окупается плохо.** На 57 общих вопросах она точнее дешёвой на 9 процентных пунктов (58 % против 49 %), но верный ответ у неё дороже в 30 раз.
4. **Ограничение этапа:** 55 % вопросов остаются без верного ответа. Основные причины: поиск возвращает не ту статью, а агент тратит 4-5 шагов на чтение длинных страниц. На это направлен этап 2.

### Этап 2. RAG и память

1. **С векторной базой ответы на дешёвой модели стали и точнее, и дешевле.** На прошлой неделе дешёвая модель с живым поиском отвечала верно на 45 % вопросов по $0.002 за верный ответ. С векторной базой та же модель в варианте «RAG всегда» отвечает верно на 89 %, а верный ответ стоит $0.00009, в 22 раза дешевле. Выигрыш даёт не модель, а то, что лежит у неё в контексте: вместо нескольких шагов поиска и длинных страниц Википедии она сразу получает пять подходящих абзацев.
2. **Модель посильнее почти ничего не добавляет.** Haiku с тем же RAG отвечает верно на 92 %, дешёвый агент, который сам решает, когда и что искать, - на 90 %. Это разница в пределах разброса: два прогона одного и того же агента дали 92,9 % и 90,3 %. При этом верный ответ у агента в 4 раза дешевле, чем у Haiku, а у «RAG всегда» на дешёвой модели ещё вдвое дешевле, чем у агента.
3. **Слабое место - поиск, а не модель.** Агент ошибается на 15 вопросах из 154, и в 11 из них нужного куска нет среди найденного. Причина может быть в запросах: агент ищет не по вопросу, а по короткому запросу, который пишет сам, и в 8 из 11 таких случаев поиск по полному вопросу нужный кусок находил. Отсюда следующий шаг: искать сразу по запросу агента и по исходному вопросу.
4. **Отказы.** На 10 вопросах, ответа на которые в базе нет, все варианты с базой честно отвечают `NOT_FOUND`, а сильная модель без инструментов на одном выдумывает ответ. Цена осторожности - лишние отказы там, где ответ есть: 14 из 154 у «RAG всегда» на дешёвой модели и по 8 у агента и Haiku.
5. **Память дешевле истории.** Агент помнит пользователя через короткие факты, а не через всю переписку. На диалоге из 10 реплик на вход уходит в 3,9 раза меньше токенов, а во второй сессии агент знает темы пользователя, хотя первая сессия в контекст не попала.

Подробности, таблицы и разобранные провалы - в [docs/02-rag-memory.md](docs/02-rag-memory.md).

## Как запустить

Зависимости ставит [uv](https://docs.astral.sh/uv/): список лежит в `pyproject.toml`, точные версии в `uv.lock`.

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh   # установить uv, если его ещё нет
uv sync                                            # создать .venv и поставить зависимости
cp .env.example .env                               # и вписать ключ OpenRouter: https://openrouter.ai/keys
uv run jupyter lab                                 # открыть ноутбук из папки notebooks/
```

В VS Code или PyCharm выберите `.venv/bin/python` ядром ноутбука. Если ключа в `.env` нет, ноутбук сразу остановится с понятной ошибкой.

Ноутбуки не тратят деньги повторно: если запись диалога по вопросу уже лежит в `traces/`, ответ берётся из неё, а модель не вызывается.

### Векторная база Milvus

Второму этапу нужна векторная база [Milvus](https://milvus.io). Она запускается в Docker одной командой из корня репозитория:

```bash
docker compose up -d        # поднять базу на localhost:19530, первый раз скачивается образ около 1 ГБ
docker compose ps           # подождать, пока статус станет healthy
docker compose down         # остановить, данные сохранятся
docker compose down -v      # остановить и стереть данные
```

Посмотреть коллекции глазами можно в веб-интерфейсе Attu: `docker compose --profile ui up -d`, затем открыть http://localhost:8000.

### Без Docker и в Kaggle

Без Docker подойдёт Milvus Lite: та же база, но живёт в одном файле рядом с ноутбуком и ставится как обычный пакет. Код ноутбука от этого не меняется, меняется только адрес базы.

```bash
uv sync --extra lite                    # поставить Milvus Lite
echo "MILVUS_URI=milvus.db" >> .env     # база будет в файле milvus.db
```

В Kaggle:

1. **Ключ.** В меню редактора **Add-ons → Secrets** добавьте секрет `OPENROUTER_API_KEY`, включите галочку напротив него и перезапустите сессию.
2. **Интернет.** В правой панели **Settings** включите **Internet**. Переключатель работает только после подтверждения телефона в профиле Kaggle.
3. **Данные.** Загрузите содержимое папки `data/` как датасет с именем `ai-agent-events-data` и подключите его к ноутбуку через **Add Input**.
4. **Пакеты и база.** Добавьте в начало ноутбука ячейку:

   ```python
   %pip install -q pymilvus milvus-lite pypdf
   import os
   os.environ["MILVUS_URI"] = "milvus.db"
   ```
